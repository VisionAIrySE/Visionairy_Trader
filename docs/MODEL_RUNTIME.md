# Bounded ghost assessment

The dashboard exposes a synthetic example through authenticated `POST /api/assessment/start` and `GET /api/assessment`. Starting requires the explicit ghost-review header and a fixed bounded request. No browser-provided account numbers, arbitrary prompts or execution actions are accepted. GET/status calls do not start paid model calls.

The example reuses `mechanics_demo.run_demo()` and its first deterministic shared-capital snapshot, excluding later outcomes. Ling extracts evidence; Nemotron compares the frozen options and cash, with Ling as the qualified research fallback. Numeric terms remain engine-owned. The output is a paper-review interpretation, not a current-market buy recommendation. Sources, document versions, cutoff, model/provider, generation ID, prompt/schema/input hashes, raw outputs, failures, elapsed time and usage/cost are retained.

The private Supabase `assessment-store` function connects directly to the existing database and uses only namespaced rows in `trader.jobs`, `trader.job_attempts` and `trader.cost_entries`. It does not expose the private schema through the Data API, add public table access, alter RLS or provide arbitrary SQL. Render authenticates with a scoped random server token; only its SHA-256 digest is in function source. The browser receives neither that token nor the OpenRouter key. The function validates its own bearer authentication; gateway JWT checking is disabled only for that authenticated server-to-server path.

Reservations are serialized under a database advisory lock. The existing $25 monthly operating ceiling includes recorded cost entries and unresolved model reservations. Each call reserves a conservative input/output bound with provider price ceilings; each example job is additionally capped at $0.10 reserved/known spend. These are control limits, not expected charges. Unknown calls retain their reserve; no automatic retry occurs. Only the qualified research fallback can receive a separate bounded call. Calls have 60-second socket timeouts; unfinished jobs have a five-minute lease and become review-required, rather than silently restarting. Identical evidence/model/prompt versions reuse a completed result across app restarts. Failed or interrupted identities cannot be replayed automatically.

Exact source-quote matching, schema validation, option allowlists and model-ID checks fail closed. They do not prove semantic truth, causal value or profitability. The report retains deterministic baseline agreement; incremental decision value and learning adoption remain unestablished. No real order, risk/preference change or automatic strategy adoption is implemented.

The continuously running discovery scanner, broad market coverage, verified live news ingestion, independently evaluated retrieval/embeddings, notification delivery and held-out/forward strategy validation remain separate unfinished work. Tradier supports symbol-list streaming; full-universe discovery cannot be inferred from a watchlist stream. The current Render free web-service plan is not qualified for uninterrupted session monitoring.

Server configuration uses Render's existing secret settings: `OPENROUTER_API_KEY`, `ASSESSMENT_STORE_URL` and `ASSESSMENT_STORE_TOKEN`. The current store URL is pinned to the designated trader project. No new paid plan or recurring model-comparison subscription is created.

Verification: research and dashboard tests include future-evidence exclusion, immutable numeric terms, source matching, output override rejection, qualified fallback/failed-call cost retention, no replay after unknown outcomes, completed-result reuse, private reads and bounded authenticated starts. Hosted call receipts and the release verification record must be inspected before claiming the hosted example works. This integration does not by itself complete LLM02's independent incremental-value gate or the operating-ghost milestone.
